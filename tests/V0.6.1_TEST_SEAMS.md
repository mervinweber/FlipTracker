# v0.6.1 Regression Test Seams

The current test runner can exercise framework-independent exports directly. It
cannot safely invoke Convex mutation handlers without mocking Convex internals,
which this test pass intentionally avoids.

## Lifecycle transitions

Extract a pure function from `convex/listings.ts` with a contract similar to:

```ts
deriveListingLifecycle(existingListing, asset, patch, now): {
  listingPatch;
  assetPatch;
  saleUpsertKey?: { listingId: string };
  saleRecord?: object;
  priceHistoryRecord?: object;
}
```

That seam would allow regression tests for Draft -> Active -> Sold transitions,
preservation of purchase price, exactly one sale per listing, and repeated Sold
updates without inserting duplicate sales.

## Sales Tracker import

Extract record normalization and a stable identity key from
`convex/listings.ts#importSalesTracker`:

```ts
normalizeSalesTrackerItem(rawItem): NormalizedImportItem
salesTrackerImportKey(item, platform): string
```

The key should use a durable external identifier when available and a documented
fallback otherwise. Tests can then prove that replaying the same import is
idempotent. The current handler always inserts new assets and listings, so there
is no pure deduplication contract to test yet.

## Generic inventory import

Extract the row normalization and duplicate decision from
`convex/assets.ts#importMany`:

```ts
normalizeImportedAsset(rawItem): NormalizedAsset
assetImportKey(item): string | undefined
decideAssetImport(existingKeys, item): 'insert' | 'skip' | 'update'
```

Tests should cover UPC/ISBN normalization, whitespace/case normalization, empty
identifiers, and duplicate rows within one file and across repeated imports.

## eBay sold-order replay

Extract the matching priority and replay key from
`convex/ebay.ts#reconcileSoldOrderLine`:

```ts
ebayOrderLineKey(orderId, orderLineItemKey): string
selectListingForOrderLine({ externalListingId, sku }, candidates): MatchResult
```

The existing database index provides the runtime replay guard. A pure seam would
verify external listing ID precedence over SKU, unmatched-order import behavior,
and stable no-op results for a repeated order line without a Convex mock.
